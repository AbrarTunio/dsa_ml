Before you start

What you will build and how this lab works.

Scikit-learn gives every model the same three verbs: fit, predict and score. Once you know them, swapping a linear regression for a decision tree is a one-line change. The hard part of machine learning is not calling the model. It is setting up an honest test and choosing a metric that tells the truth.

By the end of this lab you can

  1. Split a dataset into training and test sets with train_test_split, and explain test_size, random_state and stratify.
  2. Fit linear regression, k-nearest-neighbours, decision trees and logistic regression with the same API.
  3. Spot overfitting by comparing training and test scores.
  4. Read a confusion matrix and pick between accuracy, precision, recall and F1 on imbalanced data.

The uniform API

# the same pattern for every model
model = SomeModel(hyperparams)
model.fit(X_train, y_train)   # learn
y_pred = model.predict(X_test) # use
model.score(X_test, y_test)    # judge

X is a 2-D table of features (rows are samples). y is a 1-D array of labels or target values.

Part 1 · The train/test split and a first model

A model graded on the data it studied gets a fake grade. Hold some data back.

If you test a model on the same rows it trained on, you measure memory, not learning. train_test_split shuffles the rows and sets a fraction aside as the test set. The model never sees those rows during fit, so its score on them estimates how it will do on new data.

Three arguments matter:

  • test_size=0.2 keeps 20% of rows for testing. 20–30% is typical.
  • random_state=42 fixes the shuffle so you (and your teacher) get the same split every run.
  • stratify=y keeps the class proportions the same in both sets. Essential when one class is rare.

A first model: linear regression

When the target is a number (house price, blood-sugar level), use regression. LinearRegression fits a weighted sum of features. Its score returns R², where 1.0 is perfect and 0 means “no better than predicting the mean”.

Part 2 · Classification: KNN, decision trees and logistic regression

Three very different ideas, one identical API.

k-nearest neighbours

Stores the training data. To classify a new point, finds the k closest training points and takes a majority vote. Distance-based, so features must be on similar scales.

Decision tree

Learns a sequence of yes/no questions (“petal length < 2.45?”). Easy to read, no scaling needed, but a deep tree memorises noise. Limit it with max_depth.

Logistic regression

Despite the name, a classifier. Fits a linear boundary and outputs a probability with predict_proba. A strong, fast baseline.

Why the lines don’t move when you change k: this chart is not a single model. Each dot is a separate KNN model trained with a different k (1, 3, 5 … 25), so every value of k is already plotted. Moving the k slider moves the dashed marker to the model you picked and updates the numbers above. The lines only change if the data or the split changes.
How to read it
  • Left side (small k): overfitting. At k = 1 every training point is its own nearest neighbour, so training accuracy is always 1.00, but test accuracy is much lower. The model has memorised noise.
  • Middle: the sweet spot. The best k is where test accuracy peaks, not training accuracy.
  • Right side (large k): underfitting risk. The boundary becomes very smooth. With enough neighbours KNN drifts toward predicting the majority class everywhere.
  • Why test can beat train here: the test set has only 21 points, so one point is worth almost 5%. Small test sets give noisy scores. That is why real projects use more data or cross-validation (cross_val_score).

Part 3 · Evaluation: the confusion matrix and the right metrics

Accuracy counts correct answers. It cannot tell which mistakes you made.

Picture a fraud detector where 1 in 10 transactions is fraud. A “model” that always says not fraud scores 90% accuracy and catches zero fraud. The confusion matrix exposes this by counting four outcomes separately.

In scikit-learn, confusion_matrix(y_true, y_pred) puts actual classes in rows and predicted classes in columns. For binary labels 0/1 it is [[TN, FP], [FN, TP]].

  • Precision = TP / (TP + FP). Of everything flagged positive, how much was right? Matters when false alarms are costly (spam filter deleting real email).
  • Recall = TP / (TP + FN). Of all real positives, how many did we catch? Matters when misses are costly (cancer screening).
  • F1 = harmonic mean of precision and recall. High only when both are high.
